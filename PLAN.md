# План: от пустого репозитория до работающей v0

**Цель:** система, в которой перф-случай — поднять машины, поставить
постгрес, прогнать тест, снять метрики, свернуть — описан одной программой
на Go, выполняется внутри системы и переживает падение чего угодно.

**Раскладка:** k3s держит записи и владение, Temporal держит ход дела,
Crossplane даёт ресурсы, наш оператор сшивает первое со вторым, агент
выполняет на машинах. Обоснования — в `FORM.md`, «зачем» — в `VISION.md`.

**Из v0 выброшено:** UI, TUI, языки кроме Go, генерация типов из CRD, кэш
по содержимому.

## Постоянные ограничения

Действуют в каждой задаче, повторять не буду.

- Go; никаких `replace` в `go.mod` — зависимости берутся с GitHub.
- Обязательный набор репозитория: `README.md`, `AGENTS.md`, `Makefile` с
  целями `configure` и `help`, каталог `bin/` с прибитыми версиями
  инструментов. Ни одного `latest`, ни одной глобальной установки.
- Коммиты — Conventional Commits, без приписок об ИИ.
- `make test` и `make lint` зелёные перед каждым push: 0 падений, 0 issues.
  Где линтер неправ — исключение в `.golangci.yaml` **с записанной
  причиной**, никогда голый `//nolint`.
- Документация — текущее состояние, а не журнал изменений.

## Раскладка репозитория

`github.com/graphene-ci/graphene`, один модуль. Второй (`/sdk`) выделяется
тогда и только тогда, когда тест на граф импортов начнёт мешать
по-настоящему.

```
api/v1/                   наши виды: структуры, deepcopy, scheme
pkg/pipeline/             SDK, который импортирует ПОЛЬЗОВАТЕЛЬ
pkg/lib/docker/           обёртки-полезности: пример, а не каталог
pkg/agent/                контракт примитивов агента (общий с pkg/pipeline)
cmd/graphene/             CLI: devkit и клиент
cmd/graphene-operator/    операторы
cmd/graphene-worker/      системный воркер
cmd/graphene-agent/       агент
internal/                 всё, чего не импортируют снаружи
deploy/                   манифесты установки
examples/perf/            пример, он же первый настоящий пользователь
VISION.md FORM.md PLAN.md
```

Что здесь важно: **`pkg/pipeline` импортирует пользователь**, поэтому он не
имеет права тянуть controller-runtime, клиент кубера и облачные SDK. Это
проверяется тестом, а не намерением.

## Вехи

Каждая названа своим **доказательством**, а не списком работ. Веха
считается взятой, когда доказательство воспроизводится на чистой машине.

| | Веха | Доказательство |
|---|---|---|
| **M0** | Репозиторий, окружение, скелет devkit | `make configure && make up && make test` на чистой машине |
| **M1** | Сшивка: запись → воркфлоу → запись | Создали `Run` — воркфлоу поехал, запись создана, готовность дошла, `Run` завершён. Убили оператора посреди — доехало |
| **M2** | Агент | Шаг доехал до машины и вернул код возврата и вывод |
| **M3** | Облако | Пайплайн поднял настоящую ВМ и выполнил на ней команду |
| **M4** | Владение и снос | Отмена и убийство управляющего не оставляют мусора; `Keep` оставляет стенд |
| **M5** | Аренда и выбор | Два прогона одновременно не взяли одну машину |
| **M6** | Артефакты и наблюдаемость | Отчёт в хранилище; «почему стояло восемь минут» — одна трасса |
| **M7** | Полное API | Весь путь проходится CLI, `kubectl` не нужен ни разу |
| **M8** | Перф-случай | Настоящий прогон, которым пользуется человек не из нашей команды |

**CLI существует с M0** и растёт вехами: `up` в M0, `push`/`run`/`watch` в
M1, `logs` в M2. Devkit раньше примеров — иначе примеры негде запускать.

Подробно расписаны M0 и M1. Следующая веха детализируется, когда доехала
предыдущая: расписывать M5 сегодня — сочинять, потому что половина
предположений умрёт о первую проверку.

# M1. Сшивка: запись → воркфлоу → запись

**Доказательство:** `graphene push` кладёт образ примера и пишет
`Pipeline` с `PipelineRevision`; `graphene run` создаёт `Run`; оператор
поднимает воркфлоу; воркфлоу через системный воркер создаёт запись и
дожидается её готовности; `Run` переходит в завершённый. Оператор убит
посреди — после перезапуска всё доезжает.

Ни облака, ни агента: примером служит запись, готовность которой ставит
что-нибудь простое — для этого в M1 заводится наш собственный
игрушечный вид `Probe`, чтобы не тащить провайдера ради проверки сшивки.

### Задача 1.1: виды и манифесты CRD

**Файлы:**
- Создать: `api/v1/groupversion.go`, `api/v1/pipeline_types.go`,
  `api/v1/run_types.go`, `api/v1/probe_types.go`
- Создать: `deploy/crd/` (порождается `controller-gen`)
- Тест: `api/v1/types_test.go`

**Интерфейсы:**
- Отдаёт наружу: `v1.Pipeline`, `v1.PipelineRevision`, `v1.Run`, `v1.Probe`;
  `v1.AddToScheme(*runtime.Scheme) error`; `v1.GroupVersion`.

Поля, которые нужны уже сейчас:

- `Pipeline`: имя; политика (срок хранения прогонов); расписания —
  список `{имя, cron, параметры}`.
- `PipelineRevision`: **дайджест образа** (не тег), имя очереди, схема
  параметров и список требований (пишет воркер при старте), владелец —
  `Pipeline`.
- `Run`: ссылка на ревизию, параметры (сырой JSON), статус: фаза, id
  воркфлоу, результат (жёсткий предел размера), причина остановки.
- `Probe`: ничего в спеке, готовность ставит его оператор через
  заданную задержку. Существует ради проверки сшивки.

**Интерфейсы:**
- Отдаёт наружу: `pipeline.Serve(fn any, opts ...Option) error`;
  `pipeline.Apply[T runtime.Object](run Run, name string, obj T) Ref[T]`;
  `pipeline.Await[T](run Run, ref Ref[T]) T`; `pipeline.Run` с методами
  `Teardown(error)`, `Keep(time.Duration)`, `Sleep(time.Duration)`.

  Ограничение — **`runtime.Object` из apimachinery, а не `client.Object`
  из controller-runtime**: второе притащило бы в пользовательский пайплайн
  весь controller-runtime, и тест на граф импортов упал бы в тот же
  коммит. Это первое место, где охрана срабатывает по делу.

- [ ] **Шаг 1.** **Тест на граф импортов** — тот, что не даёт SDK
  растолстеть:

func TestSdkStaysThin(t *testing.T) {

		"github.com/graphene-ci/graphene/api/",
		"github.com/graphene-ci/graphene/pkg/agent",
		"go.temporal.io/sdk/",
		"k8s.io/apimachinery/",
		"encoding/", "time", "fmt", "errors", "context",

}
