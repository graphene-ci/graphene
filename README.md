# graphene

Pipeline и инфраструктура одним кодом, с семантикой durable-выполнения.

Программа на Go описывает и то, что нужно создать в мире (машины, кластеры,
записи), и то, что на этом нужно выполнить (шаги, команды, проверки).
Программа переживает падение чего угодно — управляющего, воркера, машины —
и доводит дело до конца или до честного сноса.

Зачем это нужно и для кого — [`VISION.md`](VISION.md).
Из чего это устроено и кто что выполняет — [`FORM.md`](FORM.md).
Путь от пустого репозитория до v0 — [`PLAN.md`](PLAN.md).

## Из чего состоит

| Слой | Кто | Ответственность |
|---|---|---|
| Записи и владение | k3s (наши CRD + Crossplane) | что существует в мире и кто за это отвечает |
| Ход дела | Temporal | что происходит и на чём остановилось |
| Ресурсы | Crossplane | создание настоящих вещей у провайдеров |
| Сшивка | наш оператор | запись `Run` → воркфлоу, готовность записи → сигнал |
| Выполнение на машинах | наш агент | пять примитивов: exec, put/fetch, stat, signal, facts |

Правило, из которого всё следует: **записи — про мир, Temporal — про ход**.

## Раскладка

```
api/v1/                   наши виды: структуры, deepcopy, scheme
pkg/pipeline/             SDK, который импортирует ПОЛЬЗОВАТЕЛЬ
pkg/agent/                контракт примитивов агента (общий с pkg/pipeline)
pkg/lib/                  обёртки-полезности поверх примитивов
cmd/graphene/             CLI: devkit и клиент
cmd/graphene-operator/    операторы
cmd/graphene-worker/      системный воркер
cmd/graphene-agent/       агент
internal/                 всё, чего не импортируют снаружи
deploy/                   манифесты установки и локальное окружение
examples/                 примеры, они же первые настоящие пользователи
```

`pkg/pipeline` импортирует пользователь, поэтому он не имеет права тянуть
controller-runtime, клиент кубера и облачные SDK. Это проверяется тестом
(`pkg/pipeline/imports_test.go`), а не намерением.

## Как собрать и проверить

Ничего не ставится в систему: `make configure` кладёт все инструменты
прибитых версий в `bin/`.

```sh
make configure   # инструменты в bin/, зависимости
make test        # тесты
make lint        # линтер
make help        # все цели
```

## Локальное окружение

```sh
make up          # k3s в docker, Temporal, Crossplane — и проверка готовности
make down        # снести целиком
```

`make up` не трогает `~/.kube/config`: доступ к кластеру лежит в
`.kubeconfig` в корне репозитория и сносится вместе с ним. Поэтому вне
`make` нужен явный указатель:

```sh
KUBECONFIG=./.kubeconfig ./bin/kubectl get pods -A
KUBECONFIG=./.kubeconfig go run ./cmd/graphene up
```

Наружу проброшено: `localhost:7233` — фронтенд Temporal, `localhost:8233` —
его веб-интерфейс, `localhost:6443` — API кластера. Порты прибиты в
`deploy/local/k3d.yaml`; поменять их — значит пересоздать кластер.

## Требования к машине

Go, docker, kubectl, helm. Версию Go, на которой всё собирается (`GO_VERSION`
в `Makefile`), Go скачает себе сам — ставить её в систему не нужно.
Остальные инструменты кладёт в `bin/` цель `configure`.
